# v1.3 — Generative media *(image + speech)*

**Goal:** ocai stops being "one interface for LLMs" and becomes "one interface
for **generative AI**." This milestone adds the modalities with no port today:
**image generation/editing** and **speech both directions** (TTS + STT). It also
lands the IR change that has loomed since the design docs — a **typed multimodal
content-part union** — which simultaneously upgrades chat (vision) and feeds
these new ports.

**Provider added:** none new — exercise the image/audio endpoints of the three
providers already integrated (and one dedicated audio provider if needed).

**Done when:** a caller can generate/edit an image, synthesize speech, and
transcribe audio through neutral ports; and a `ChatRequest` can carry an image or
document content part that round-trips through the conversion graph with the loss
`Report` honest about any modality a target can't accept.

**Not in scope:** video generation and realtime/bidirectional voice (v1.4); OCR
beyond what transcription/vision already give (revisit after).

**Parallelism:** 8.1 (content-part IR) **gates** 8.2 and 8.5. 8.3 and 8.4
(speech) are independent of 8.1 and of each other.

> Read the root [CLAUDE.md](https://github.com/ocarinow/ocai/blob/main/CLAUDE.md) first. The content-part union is the
> one IR change here — it is **additive** (`content: str | None` stays valid;
> parts are a new shape), and every conversion that drops a part **must report
> it**, per rule 4. This is the largest fidelity-honesty test in the roadmap.

---

## WU 8.1 — Typed multimodal content-part union  ·  depends on: v1.0  ·  GATES 8.2, 8.5

- [ ] Extend IR `Message.content` to accept an ordered list of typed parts:
      `text`, `image`, `document`, `audio` (each carrying inline bytes/uri or a
      v1.2 `FileRef`). Keep `str | None` valid (additive). Update `spec/` schema +
      golden fixtures; older fixtures must still validate.
- [ ] Each adapter maps parts to its wire shape (Gemini `parts[]`, Anthropic
      content blocks, OpenAI input) and **records loss** when a target rejects a
      modality (e.g. audio into a text-only model).

**Done:** a multimodal `ChatRequest` round-trips through canonical to each
provider; conversions to a modality-incapable target produce a valid payload +​ a
`Report` naming exactly the dropped part.

---

## WU 8.2 — `ImageModel` port  ·  depends on: 8.1

- [ ] Neutral port for text→image **generation**, **edit/inpaint**, and
      **variation**, returning typed image parts (reusing 8.1) + cost. One
      adapter, recorded fixtures, golden conformance.

**Done:** generate / edit / vary all work against recorded fixtures and return
canonical image parts with cost reported.

---

## WU 8.3 — `SpeechModel` (text→speech) port  ·  depends on: v1.0

- [ ] Neutral TTS port (`synthesize(text, voice, format) -> audio`), returning a
      typed audio part. One adapter, recorded fixtures, cost wired.

**Done:** text synthesizes to audio against recorded fixtures with cost reported.

---

## WU 8.4 — `TranscriptionModel` (speech→text) port  ·  depends on: v1.0

- [ ] Neutral STT port (`transcribe(audio) -> text + segments`), accepting an
      audio part or a v1.2 `FileRef`. One adapter, recorded fixtures, cost wired.

**Done:** audio transcribes to text (with segment timing where available) against
recorded fixtures, cost reported.

---

## WU 8.5 — Video generation via `Operation`  ·  depends on: 8.1, 6.4  ·  *(deferrable)*

- [ ] Neutral `VideoModel` port whose generate call returns an `Operation`
      (v1.1) the caller polls. Returns a typed video part. One adapter, recorded
      fixtures. Deferrable — lands only if a provider's video API is stable enough
      to fixture honestly.

**Done:** a video generate request submits, polls to completion via `Operation`,
and returns a canonical video part with cost — or this WU is explicitly deferred
in the milestone with a one-line reason.
