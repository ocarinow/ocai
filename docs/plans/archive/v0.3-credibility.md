# v0.3 — Credibility & version-resilience proof

**Goal:** complete the mandatory features AND explicitly prove the headline claim
that *provider version changes are ocai's problem, not the user's*.

**Provider:** add Gemini (validates the abstraction generalizes to a genuinely
different wire format).

**Done when:** tools and structured output behave uniformly across three
providers; capabilities are queryable; routing is predictive; the version-bump
demo shows zero user-code change; embeddings + one vector store work.

**Not in scope:** polyglot, observability backends.

**Parallelism:** 3.7 parallel throughout. 3.6 is fully independent (different
domain) — ideal for a dedicated instance. 3.1/3.2 parallel. 3.3 → 3.4. 3.5
independent once the graph exists.

> Read the root [CLAUDE.md](https://github.com/ocarinow/ocai/blob/main/CLAUDE.md) rules first. One WU per PR.

---

## WU 3.1 — Tool / function calling normalized  ·  depends on: v0.2

- [ ] Normalize tool definitions, tool choice, parallel tool calls, and
      tool-result threading across OpenAI, Anthropic, Gemini.
- [ ] `tool_calls.arguments` is an object in the IR; adapters `json.loads` /
      re-serialize string arguments at the boundary. Consider a typed
      `ToolDef(name, description, parameters)`.

**Done:** the same tool-using request produces correct provider-shaped tool
payloads on all three, and tool-call responses decode to the same canonical
`ToolCall`s; golden fixtures cover each.

---

## WU 3.2 — Structured output / JSON mode normalized  ·  depends on: v0.2

- [ ] Neutral structured-output request (schema / JSON mode) mapped to each
      provider's placement (OpenAI `response_format`, Gemini schema config,
      Anthropic tool-based). Loss recorded where a provider can't enforce.

**Done:** a single structured-output request works across all three providers
with fixtures; unsupported enforcement is reported as loss, not silently dropped.

---

## WU 3.3 — Capability introspection  ·  depends on: 1.1

- [ ] Query a model for: vision, tools, context window, streaming, JSON support.
      Mirror each provider's `GET /models` capability data via
      `ChatModel.capabilities()`.

**Done:** `capabilities()` returns a typed, comparable capability set per model
on all three providers.

---

## WU 3.4 — Capability-aware predictive routing  ·  depends on: 3.3, 2.5

- [ ] Upgrade fallback to skip incapable targets **pre-flight** (not only on
      error) — e.g. don't route a vision request to a text-only model.

**Done:** the router filters fallback candidates by required capabilities before
sending; tests show an incapable target is skipped without a failed request.

---

## WU 3.5 — Version-codec proof  ·  depends on: 2.3  ·  ⭐ FLAGSHIP

> **This WU proves the marketing claim — treat it as a flagship.**

- [ ] Ship a second wire version for one provider (e.g. OpenAI `v1` +
      a `v2`/Responses-style codec) as separate `(provider, version)` graph nodes.
- [ ] Demonstrate **user code is unchanged across the bump.** Golden fixtures for
      both versions.

**Done:** the same user-facing call works against both wire versions with zero
user-code change; a runnable demo + fixtures prove it; the `Report` shows the
version routing.

---

## WU 3.6 — Embeddings + vector store  ·  depends on: 1.1 (independent domain)

- [ ] `EmbeddingModel` port + one embeddings provider.
- [ ] `VectorStore` port + pgvector adapter, plus an in-memory store for tests.

**Done:** embed → upsert → query works end to end against the in-memory store in
CI (and pgvector when available); makes the RAG claim credible.

---

## WU 3.7 — Gemini adapter  ·  depends on: v0.2

- [ ] Gemini `generateContent`: chat / streaming / errors / tools, recorded
      fixtures. `contents`/`parts`, `systemInstruction`, `assistant`↔`model`.

**Done:** Gemini works against recorded fixtures and normalizes to the same
canonical types, error taxonomy, and `ChatChunk` stream as the others; codec +
fixtures green.
