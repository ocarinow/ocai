# v1.1 — Honest economics *(first expansion-track milestone)*

**Goal:** extend the differentiator — "every conversion reports what it cost" —
from **tokens** to **money and pre-flight estimates**. ocai already reports
fidelity loss; this milestone makes it report *spend* with the same honesty. No
new modality, no SDK: pure leverage on ports that already exist.

**Provider added:** none. Breadth across providers is frozen at three until the
economics story is solid on them.

**Done when:** before sending a request you can ask "how many tokens / how many
dollars is this, on each candidate provider?" and after sending it the `Report`
carries actual spend in currency — across a multi-hop conversion and a fallback
retarget. A batch of requests can be submitted async and polled to completion.

**Not in scope:** new modalities, fine-tuning, billing/quota enforcement (we
*report* cost, we don't gate on it).

**Parallelism:** 6.1 and 6.5 are independent and unblock the rest. Core path is
(6.1, 6.5) → 6.3 → 6.4; 6.2 is independent.

> Read the root [CLAUDE.md](https://github.com/ocarinow/ocai/blob/main/CLAUDE.md) rules first. Every WU here is an
> **additive** change to the v1.0-frozen `ocai.core` API — new ports, new
> optional fields, new middleware. Nothing is renamed or removed. This milestone
> is itself a proof of the additive-extensibility promise.

---

## WU 6.1 — `TokenCounter` port + pre-flight  ·  depends on: v1.0

- [ ] New neutral port `TokenCounter` with `count(request) -> TokenEstimate`
      (prompt tokens + a context-window-fit check). Provider-native where it
      exists (Anthropic `count_tokens`, Gemini `countTokens`), local estimate
      otherwise — and the `TokenEstimate` records **which method was used** so an
      estimate is never silently passed off as exact.
- [ ] Recorded fixtures for the native endpoints; deterministic local estimator
      tested against them for drift.

**Done:** a caller can pre-flight any `ChatRequest` against a model and learn
token count, fit-vs-context-window, and whether the number is exact or estimated
— without sending the request.

---

## WU 6.2 — Grow `Usage` with cache/reasoning fields  ·  depends on: v1.0

- [ ] Add optional `cache_read_tokens`, `cache_write_tokens`, `reasoning_tokens`
      to `Usage` (additive). Adapters populate them where the provider reports
      them; absent → `None`, never `0`-as-unknown.

**Done:** response `Usage` distinguishes fresh vs cached vs reasoning tokens for
providers that expose them; the canonical schema + golden fixtures are updated;
older fixtures still validate (additive proof).

---

## WU 6.3 — Cost model: tokens → currency  ·  depends on: 6.2, 6.5

- [ ] Per-`(provider, wire_version, model)` price table lives in `spec/` (the
      neutral source of truth), versioned alongside the model registry, with an
      explicit `as_of` date so a stale price is visible, not silent.
- [ ] `Report` and `ChatResponse` carry an estimated/actual `Cost` (currency +
      input/output/cache breakdown). A conversion `Report` can answer "this
      retarget moved you from $X to $Y."

**Done:** a converted/retargeted request prints what it cost in dollars on the
source vs target provider, with the price-table `as_of` date shown. Missing
price data degrades to "unknown", never to a wrong number.

---

## WU 6.4 — Batch submission + `Operation` polling primitive  ·  depends on: 6.1

- [ ] A neutral `Operation[T]` handle (submit → poll `status` → `result`/`error`)
      — the shared abstraction for *every* long-running provider job (batch now;
      video gen, fine-tune later all reuse it).
- [ ] Batch path on the chat surface (OpenAI Batch, Anthropic Message Batches):
      submit N canonical requests, poll, collect N canonical responses + a merged
      cost `Report` showing the batch discount.

**Done:** N requests submit as one batch against recorded fixtures, poll to
completion through `Operation`, and return canonical responses with a cost
`Report` that reflects the batch price tier.

---

## WU 6.5 — Model registry / discovery port  ·  depends on: v1.0

- [ ] New port `ModelRegistry` (`list_models()`, `describe(model)`) surfacing
      capabilities (tools, vision, streaming, thinking, caching), context window,
      and modalities — mirroring each provider's `GET /models`, normalized.
- [ ] Feeds 6.1 (context-window fit) and 6.3 (which prices apply).

**Done:** callers introspect what a model supports and its limits through one
neutral port instead of discovering by 400; backed by recorded fixtures.
