# v1.2 — Retrieval, completed

**Goal:** finish the RAG pillar. Today "RAG" means one `VectorStore` port (still
a stub). Real retrieval needs **reranking** (the biggest relevance lever) and a
**Files** lifecycle (the thing multimodal and batch both lean on). This
milestone also draws the scope line: ocai provides retrieval *primitives*, not a
document-processing framework.

**Provider added:** none new for chat; adds a rerank provider (e.g. Cohere or
Voyage) and exercises the Files endpoints of existing providers.

**Done when:** a caller can upload a document once and reference it across
requests, run a vector query, and rerank the hits through neutral ports — each
backed by recorded fixtures and golden conformance.

**Not in scope (explicit non-goals):** chunking, parsing, loaders, embedding
orchestration, prompt-stuffing helpers. ocai is the neutral *interface*, not the
pipeline framework — see WU 7.3.

**Parallelism:** 7.1, 7.2, 7.4 are independent. 7.3 is a docs/decision WU that
can land anytime.

> Read the root [CLAUDE.md](https://github.com/ocarinow/ocai/blob/main/CLAUDE.md) first. New ports only — additive to the
> frozen `ocai.core` surface.

## WU 7.1 — `Reranker` port  ·  depends on: v1.0

- [ ] Neutral port `Reranker` (`rerank(query, documents, top_n) -> ranked`),
      returning relevance scores + original indices. Adapter for one rerank
      provider, recorded fixtures, golden conformance.
- [ ] Usage/cost wired through the v1.1 economics path.

**Done:** a query + candidate documents return a neutrally-typed ranked list with
scores against recorded fixtures; cost is reported.

---

## WU 7.2 — `Files` port / object lifecycle  ·  depends on: 6.4 (`Operation`)

- [ ] Neutral port for provider object storage: `upload`, `get`, `list`,
      `delete`, with a neutral `FileRef` that adapters resolve to provider file
      ids. Large uploads surface progress via the `Operation` primitive.
- [ ] `FileRef` is referencable from a `ChatRequest` content part (forward link
      to v1.3 multimodal) and from a batch job.

**Done:** upload-once / reference-many works against recorded fixtures for at
least one provider; a `FileRef` round-trips into a request.

---

## WU 7.3 — Draw the retrieval scope line  ·  depends on: —

- [ ] Short ADR in `docs/` stating what ocai's retrieval surface **is** (vector
      store, reranker, files, embeddings) and **is not** (chunkers, parsers,
      loaders, pipeline glue). Frame it against the "neutral interface, not a
      framework" thesis so future WUs don't drift into LangChain territory.

**Done:** the boundary is written down and linked from the README; a reviewer can
reject an out-of-scope retrieval feature by pointing at it.

---

## WU 7.4 — Harden `VectorStore` to a real adapter  ·  depends on: v1.0

- [ ] Finish the stubbed `VectorStore` port against one real backend: upsert,
      query (top-k + filter), delete; hybrid/metadata passthrough via
      `provider_options`. Recorded fixtures; golden conformance.

**Done:** `VectorStore` is no longer a stub — one backend round-trips upsert →
query → delete against recorded fixtures, and reports cost where the backend
charges.
