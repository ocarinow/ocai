# v1.4 — Realtime & duplex transport

**Goal:** support **bidirectional, live** interaction (realtime voice / live
sessions — OpenAI Realtime, Gemini Live). This is the one milestone that touches
an *architectural* assumption: the `Transport` port today is request→response
plus a **one-way** byte stream. Realtime needs **full duplex (WebSocket)**.
Getting this in as an *additive sibling* — not a breaking change to the frozen
`Transport` — is the whole point.

**Provider added:** none new — use the realtime endpoints of an existing
provider.

**Done when:** a caller can open a live session, stream audio/text up while
receiving audio/text/events down, over a neutral duplex port, with the canonical
event types — and the existing middleware/economics stories still apply.

**Not in scope:** new modalities beyond what v1.3 defined; telephony/SIP
integration; multi-party sessions.

**Parallelism:** 9.1 **gates** everything. 9.2 then 9.3; 9.4 follows 9.2.

> Read the root [CLAUDE.md](../CLAUDE.md) first. **Design 9.1 as additive**: a new
> `DuplexTransport` port alongside `Transport`, not a change to it (rule 2). If
> the duplex shape ever needs to influence `Transport`, that is a design review,
> not a quiet edit. Flag this milestone's interface review early — it is the
> riskiest in the expansion track.

---

## WU 9.1 — `DuplexTransport` port  ·  depends on: v1.0  ·  GATES 9.2–9.4

- [ ] New port `DuplexTransport` (open session → concurrent send/receive of typed
      frames → close), built on a WebSocket client ocai owns end-to-end — same
      "own the wire, no provider SDK" stance as `transport.py`. Recorded-frame
      fixtures (a captured session transcript) for tests; **no live sockets in
      CI**.
- [ ] Credentials applied per-session via the existing `Credential.apply`; secrets
      redacted in any frame log.

**Done:** a fake/recorded duplex session opens, exchanges frames, and closes
through the neutral port; CI passes with no network and no secrets.

---

## WU 9.2 — Realtime session port + adapter  ·  depends on: 9.1, 8.1

- [ ] Neutral `RealtimeSession` port over `DuplexTransport`: push text/audio
      parts (reusing v1.3 content parts), receive canonical events (audio deltas,
      transcripts, tool calls, turn boundaries). One provider adapter against a
      recorded session.

**Done:** a recorded realtime session replays through the neutral port, surfacing
canonical events; tool calls during a session route through the same `ToolCall`
IR as batch chat.

---

## WU 9.3 — Canonical realtime event types  ·  depends on: 9.2

- [ ] Lock the live-session event taxonomy (analogue of `ChatChunk` for duplex):
      one neutral event union, no provider-specific frame shapes leaking through
      (rule 7, extended to realtime). Golden fixtures per event kind.

**Done:** every realtime event a caller sees is a canonical type; a second
provider's frames would map onto the same union without new public shapes.

---

## WU 9.4 — Middleware & economics over sessions  ·  depends on: 9.2

- [ ] Confirm the cross-cutting stories survive duplex: cost/usage accounting
      accrues over a session (v1.1), tracing spans wrap a session (Tracer), and
      reconnect/retry has a defined policy. Document what composes and what
      doesn't.

**Done:** a session reports cumulative token+dollar cost and emits trace spans;
reconnect behavior is specified and tested against a recorded drop.
